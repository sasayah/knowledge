## 0. 設計原則

1. **毎日30〜45分で完結する**。コマンド1発で開始し、コマンドが終了処理（保存・コミット）まで面倒を見る。ユーザーが「保存しなきゃ」と考える瞬間をゼロにする。
2. **すべてMarkdown + YAML frontmatter**。AIが `grep`/`awk` で機械的に読み書きできるよう、frontmatterのキー名・型・フォーマットを本書で固定する。
3. **インデックスファイルを持たない**。概念カードの一覧・期限などは毎回 frontmatter をスキャンして導出する（二重管理＝同期バグの温床を避ける）。唯一の例外は自動生成の `progress.md`（導出キャッシュであり、いつでも捨てて再生成できる）。
4. **凝らない**。グラフ描画・外部DB・プラグインは使わない。テキストとgit履歴だけで完結する。

### 1.1 命名規則（全ディレクトリ共通）

| 項目 | 規則 |
|---|---|
| 日付 | すべて ISO 8601 `YYYY-MM-DD`。frontmatter内もファイル名も同一表記 |
| slug | 小文字ASCII・ケバブケース（`[a-z0-9-]+`）。日本語概念は定訳の英語（例: 脱構築→`deconstruction`）、無ければローマ字（例: 世間→`seken`）。**slug＝ファイル名（拡張子除く）**であり、`related` 等の相互参照はすべてslugで行う |
| 週 | ISO週番号 `YYYY-Www`（`date +%G-W%V` で取得） |
| 四半期 | `YYYY-Qn`（1〜3月=Q1） |
| frontmatter | YAML。`---` で囲む。**各フィールドは必ず1行で書く**（`review_history` のリスト要素はフロースタイル `- {key: val, ...}` で1行）。これはgrep/awkでの抽出を成立させるための必須規約 |

### 1.2 news/ を独立ディレクトリにするかの決定

**決定: ハイブリッド方式。**
- `/today` 内のニュース適用（5〜10分の軽い演習）→ **日次ノートの `## ニュース適用` セクションに書く**。ファイルを増やさない。毎日のことなので摩擦最小を優先。
- `/news`（単発のしっかりした演習）→ **`news/` に独立ファイル**。エッセイの種になる粒度のものだけが独立ファイルになるので、`news/` は「エッセイ候補の苗床」として機能する。

## 2. データフォーマット

### 2.1 日次ノート `daily/YYYY/MM/YYYY-MM-DD.md`

```yaml
---
date: 2026-06-10          # 必須。ファイル名と一致すること
session: 42               # 必須。通算セッション番号（前日ノートのsession+1）
phase: 1                  # 必須。roadmap.mdのフェーズ番号（整数）
streak: 12                # 必須。当日時点の連続学習日数（算出規則は§2.5）
minutes: 35               # 必須。実所要分数（整数）。セッション末にAIが申告を聞いて記入
input: "『哲学史入門』第3章 pp.53-60"   # 必須。今日読んだ/聴いた範囲。無い日は ""
concepts_new: [eidos]                  # 必須。今日新規作成した概念カードのslug配列。無ければ []
concepts_reviewed: [deconstruction, episteme]  # 必須。今日復習した概念のslug配列。無ければ []
news_applied: true        # 必須。/today内でニュース適用をやったか（bool）
---
```

本文セクション（**この順序・この見出し文字列で固定**。空のセクションも見出しは残す）:

```markdown
# 2026-06-10

## 復習
（出題と回答の要約。カードごとに pass/partial/fail）

## インプット
（読んだ内容の自分の言葉での要約。AIの講義の写しではなく自分の理解）

## 理解確認
（AIの問いと自分の回答の要点）

## ニュース適用
（今日のニュース1本 × 概念レンズ。やらなかった日は「なし」）

## 今日の一行
（今日の学びを1文で。これが後のエッセイ・Xポストの種になる）

## 問答ログ
（/talk 実行時にここへ追記。なければ空）

## メモ
（疑問・脱線・明日やりたいこと）
```

### 2.2 概念カード `concepts/<slug>.md`

```yaml
---
name: 脱構築               # 必須。日本語の正式名称
level: 2                  # 必須。1〜5の整数（定義は§3.1）
created: 2026-06-01       # 必須。カード作成日
last_review: 2026-06-10   # 必須。最終復習日（作成時はcreatedと同値）
next_review: 2026-06-13   # 必須。次回復習期日。「next_review <= 今日」が出題対象
review_history:           # 必須。復習履歴。各要素は必ず1行のフロースタイル
  - {date: 2026-06-01, mode: today, result: pass, level_after: 1}
  - {date: 2026-06-10, mode: quiz, result: pass, level_after: 2}
related: [differance, logocentrism]   # 必須。関連概念のslug配列。無ければ []
source: "『現代思想入門』第2章"        # 必須。初出の教材
phase: 3                  # 必須。学習したフェーズ番号
tags: [現代思想, ポスト構造主義]       # 任意。日本語可
---
```

- `mode` の値域: `today` | `quiz` | `news` | `talk`（どのコマンド経由の復習か）
- `result` の値域: `pass` | `partial` | `fail`
- 本文の構成（固定見出し）: `## 定義（自分の言葉）` / `## 具体例` / `## 関連・対比` / `## 適用メモ`（ニュース・実務に当てはめた記録を追記していく）
- **カード更新時の規約**: AIは frontmatter の対象フィールド（`level` / `last_review` / `next_review` / `review_history` への1行追記）だけを書き換え、他のフィールドと本文は保持する。`## 適用メモ` への追記は末尾追加のみ。

### 2.4 その他のファイル

- **roadmap.md**: フェーズごとに `## Phase N: <名称>` 見出し + 「目的 / 主教材 / 完了条件 / 目安期間」の箇条書き。frontmatterは `updated` のみ。内容（どのフェーズで何を学ぶか）は初回セットアップ時にAIと対話して作る（本書のスコープ外）。
- **books.md**: Markdownテーブル1枚。列 = `タイトル | 著者 | フェーズ | 状態(候補/読書中/読了/中断) | メモ`。
- **news/ ファイル**: frontmatter = `date` / `title` / `source_url` / `lens`（適用した概念slug配列）/ `essay_seed`（bool: エッセイ候補か）。本文 = `## 要約（3行）` / `## レンズ適用` / `## 自分の見立て（200字）`。
- **essays/ ファイル**: frontmatter = `date` / `title` / `slug` / `status`（`draft` | `revised` | `published`）/ `concepts`（slug配列）/ `target`（`x` | `blog` | `note`）/ `published_url`（公開後に記入、それまで `""`）。公開時は `/essay --publish <slug>` がファイルを `essays/published/` へ `git mv` し、`status` と `published_url` を更新する。
- **reviews/ ファイル**: frontmatter = `period`（例 `2026-W24`）/ `type`（`weekly` | `monthly` | `quarterly`）/ `sessions` / `total_minutes` / `concepts_new` / `level_ups`（昇格イベント数）/ `essays`（本数）。本文はテンプレート（§8）に従う。

### 2.5 streak の算出規則（決定的アルゴリズム）

```
直前の日次ノート = daily/ 以下でファイル名日付が今日より前の最新ファイル
if 直前ノートが存在しない:            streak = 1
elif 直前ノートの date == 昨日:        streak = 直前ノートの streak + 1
else:                                  streak = 1
```

- 猶予ルールはコードに入れない（複雑化の元）。「週1回まで休んでも翌日が昨日扱い」のような救済はやらず、途切れたら1から。代わりに `progress.md` に `longest_streak` を残し、過去の達成を可視化する。
- 同日に2回 `/today` を実行した場合は新規ノートを作らず既存ノートに追記する（streakは変えない）。

### 2.6 概念カードのスキャン方法（規範コマンド）

カードが数百枚になっても破綻しないよう、出題対象の抽出は以下のワンライナーで行う（各コマンドの仕様で「§2.6の方法で」と参照する）:

```bash
today=$(date +%F)
grep -H '^next_review:' concepts/*.md \
  | awk -F': *' -v t="$today" '$3 <= t {print $3, $1}' \
  | sort | head -3        # next_reviewが古い順に最大3件
```

レベル分布の集計:

```bash
grep -h '^level:' concepts/*.md | sort | uniq -c
```

## 3. 復習アルゴリズム（簡易SRS）

### 3.1 レベル定義（L1〜L5）

| Level | 状態 | 合格基準（出題形式） |
|---|---|---|
| L1 | 聞いたことがある | 定義を見れば「ああ、あれか」と思い出せる |
| L2 | 説明できる | 何も見ずに自分の言葉で2文以内で定義を言える |
| L3 | 使い分けられる | 具体例を1つ挙げ、隣接概念との違いを説明できる |
| L4 | 適用できる | 最近のニュース・技術・自分の仕事に当てはめて読み解ける |
| L5 | 議論できる | AIの本気の反論に耐えて立場を擁護できる／エッセイで使いこなせる |

### 3.2 出題形式（レベル昇格はこの形式の問いにpassした場合のみ）

| 現level | 出題 |
|---|---|
| L1 | 「`name` とは何か。自分の言葉で2文以内で」 |
| L2 | 「具体例を1つ挙げ、`related` の概念1つとの違いを説明せよ」 |
| L3 | 「この概念で最近の出来事（AI/EC/社会から1つ）を読み解け」 |
| L4 | AIが概念の使い方に対して反論を1つ提示し、防御させる |
| L5 | 維持確認のみ（L4と同形式。落ちれば降格） |

### 3.3 レベル遷移と次回期日

判定はAIが行う（pass: 基準を満たす / partial: 方向は正しいが不正確 / fail: 答えられない・誤解している）。

| result | level変化 | next_review |
|---|---|---|
| pass | +1（上限5） | 今日 + interval(新level) |
| partial | 変化なし | 今日 + ceil(interval(level) / 2) |
| fail | −1（下限1） | 今日 + 1日 |

interval表: **L1=1日, L2=3日, L3=7日, L4=21日, L5=60日**（partial時の半分値: 1, 2, 4, 11, 30日）。

新規カード作成時: `level: 1`, `next_review: 翌日`。1日の新規カード作成は**最大2枚**（`/today` 仕様で強制。詰め込み防止）。

## 4. スラッシュコマンド仕様

`.claude/commands/*.md` はClaude Codeのカスタムコマンド（Markdownプロンプトファイル、引数は `$ARGUMENTS` で受ける）。**本節は各ファイルに書くべき仕様であり、プロンプト文面そのものは実装時に書く。**

### 4.0 全コマンド共通規約

- **言語**: 日本語。
- **読込の前提**: `CLAUDE.md` はClaude Codeが自動で読むため各コマンドの読込リストには含めない。
- **frontmatter操作**: §2の規約に厳密に従う。対象フィールド以外は保持。
- **異常系（共通）**:
  - 読むべきファイルが無い → `templates/` から生成して続行（テンプレートも無ければ最小構成で生成し、その旨を報告）。
  - frontmatterが規約違反（パース不能・日付形式違反） → 修復案を提示し、ユーザー承認後に修正してから本処理に進む。勝手に直さない。
  - シラバスに今週のブロックが無い → 先週のブロックと `roadmap.md` から今週分の案を提示し、承認後に `syllabus.md` へ追記してから続行。
- **終了処理（共通）**: §6の `progress.md` 再生成（対象コマンドのみ）→ §7のgit自動コミット → 「今日はここまで。◯分でした」の一言で終了。

### 4.1 `/today` — 日次セッション（中核）

**目的**: 復習→インプット→ニュース適用→記録 を30〜45分で一気通貫に伴走する。

**引数**: なし／`short`（30分未満モード: ニュース適用をスキップ）。

**読むファイル（この順）**:
1. `progress.md`（現在のstreak・概念数の把握）
2. 直前の日次ノート1件（前回の文脈・「明日へ」のメモ）
3. `curriculum/syllabus.md`（今週ブロック → 今日の範囲特定）
4. §2.6の方法で `next_review <= 今日` の概念カード（古い順に最大3枚、本文まで読む）
5. `method/rules.md`

**対話フロー**:
1. **オープニング（1分）**: 前回の文脈を1〜2行で要約し、今日の範囲と所要見込みを宣言。同日ノートが既にあれば「追記モード」を宣言。
2. **復習（5〜10分）**: 期限到来カードに§3.2の形式で出題（最大3枚）。1枚ごとに判定を伝え、§3.3に従いカードを更新。期限到来カードが0枚なら省略。
3. **インプット（15〜25分）**: 今日の範囲について、(a) ユーザーが既に読んでいれば理解確認の問いから、(b) 未読なら「読みどころ」を3点以内で提示→ユーザーが読む（その場で or 通勤で読了済みの想定）→理解確認。確認は最大3問。**説明より問いを優先**（CLAUDE.mdの規律）。
4. **ニュース適用（5〜10分、`short`時スキップ）**: ユーザーに今日気になったニュースを1本挙げてもらう（無ければAIが技術・EC・AI関連から1本提案）。今日学んだ概念または既存のL3以上のカード1枚をレンズに、3往復以内の問答で読み解く。
5. **クロージング（2〜5分)**: 「今日の一行」をユーザーに言わせる→所要分数を聞く→以下を書き込み:
   - 日次ノートを `templates/daily.md` から生成・保存（frontmatter全項目、§2.5でstreak算出。追記モード時は既存ノートの各セクションに追記し `minutes` を加算）
   - 新規概念があれば `templates/concept.md` からカード作成（最大2枚。slug・related はAIが提案しユーザー承認）
   - 復習・適用したカードの frontmatter 更新
   - ニュース適用で使ったカードには `review_history` に `{mode: news, ...}` を追記（適用も復習として扱う）

**書き込み**: `daily/YYYY/MM/YYYY-MM-DD.md`（新規/追記）、`concepts/*.md`（更新・新規）、`progress.md`（再生成）。

**コミットメッセージ**: `today: 2026-06-10 (streak 12, +1 concept)`

### 4.2 `/news` — ニュース1本×レンズ適用の単発演習

**目的**: ニュースに概念レンズを当てる訓練を、日次セッションと独立に行う。

**引数**: URL／貼り付けテキスト／トピック名のいずれか（必須。無ければ冒頭で要求）。

**読むファイル**: ①引数のニュース（URLならWebFetch、不可なら本文貼り付けを依頼） ② `grep -h '^level:'` でL3以上のカード一覧（slugとnameのみ。レンズ候補のため） ③ユーザーが選んだレンズのカード本文。

**対話フロー**:
1. ニュースの要点をユーザーに3行で要約させる（AIが要約しない）。
2. レンズ候補をAIが2枚提示（L3以上から）。ユーザーが選択（候補外の指定も可）。
3. ソクラテス式に3〜5往復で適用（「この概念ならこの事象のどこに注目する？」「その読みへの反論は？」）。
4. ユーザーに200字の「自分の見立て」を書かせる。AIは事実誤認と概念の誤用だけ指摘。
5. 保存: `news/YYYY-MM-DD-<slug>.md`（§2.4のフォーマット。slugはAI提案・ユーザー承認）。X投稿の種になりそうなら `essay_seed: true`。
6. 使ったカードに `{mode: news, result: 判定, ...}` を追記し§3.3で更新。当日の日次ノートが存在すれば `## ニュース適用` に1行（`→ news/ファイル名 参照`）追記。

**書き込み**: `news/YYYY-MM-DD-<slug>.md`（新規）、レンズのカード（更新）、当日ノート（あれば追記）。`progress.md` は再生成しない。

**コミットメッセージ**: `news: 2026-06-10 <slug>`

### 4.3 `/quiz` — 復習出題のみ

**目的**: スキマ時間に復習だけ回す。

**引数**: なし（期限到来分から古い順に最大5枚）／枚数 `n`／概念slug（指名復習。期限前でも出題可、ただしカード更新は期限到来分のみ）。

**読むファイル**: §2.6の方法で対象カードを抽出し、本文まで読む。

**対話フロー**: 1枚ずつ§3.2の形式で出題→回答→判定（pass/partial/fail）と根拠を1〜2行で伝える→次へ。全問終了後にまとめ（◯枚中◯pass、昇格したカード名）。

**書き込み**: 出題した各カードの frontmatter 更新（§3.3）。当日の日次ノートが存在すれば frontmatter の `concepts_reviewed` に出題slugを追加（重複は除外）。日次ノートが無くても**新規作成はしない**（/quizはセッションにカウントしない）。`progress.md` 再生成は行わない。

**コミットメッセージ**: `quiz: 2026-06-10 (5 cards, 3 pass)`

### 4.4 `/talk` — ソクラテス問答・スピーチ練習

**目的**: 「語れる」ようになる訓練。AIは反論役・評価者であり、教師ではない。

**引数**: `<テーマまたは概念slug>`（必須）＋モード `socratic`（既定）| `speech`。

**読むファイル**: ①テーマに対応する概念カード＋その `related` カード（存在すれば） ② `method/training.md`（問答・スピーチのルール詳細） ③直近の日次ノート1件（文脈）。

**対話フロー（socratic）**: AIが立場を固定して反論者になる（10〜15分目安、5〜8往復）。途中で答えを教えない。終了時に「良かった応答1つ／崩れた箇所1つ／次に読むと良い概念1つ」を講評。

**対話フロー（speech）**: ユーザーがテーマについて10分相当のスピーチをテキストで一気に書く（または分割投稿）。AIは終わるまで遮らない。終了後にルーブリック評価: **構成 / 概念の正確さ / 具体例と適用 / 自分の言葉度**（各1〜5点）＋改善点を最大3つ。

**書き込み**: 当日の日次ノートの `## 問答ログ` にモード・テーマ・講評（評価点含む）を追記。**日次ノートが無ければ `templates/daily.md` から最小frontmatter（`input: ""`, `news_applied: false`, streak・sessionは§2.5で算出）で新規作成する**（/talkだけやった日も学習日としてstreakが繋がる）。テーマが既存カードに対応する場合、`{mode: talk, ...}` を追記して§3.3で更新（speechでの議論成立はL4→L5昇格の正規ルート）。

**コミットメッセージ**: `talk: 2026-06-10 <theーマslug> (speech 16/20)` ※socratic時は点数なし

### 4.5 `/essay` — 週次エッセイの壁打ち

**目的**: 1週間の学びを公開可能な文章（X長文・ブログ）に変換する。

**引数**: なし（テーマ探しから）／テーマ文字列／`--continue <slug>`（既存下書きの続き）／`--publish <slug>`（公開処理のみ）。

**読むファイル**: ①今週の日次ノート全件（frontmatterと「今日の一行」「ニュース適用」セクション） ②今週の `news/*.md`（特に `essay_seed: true`） ③テーマに関連する概念カード ④ `essays/drafts/` の既存下書き一覧。

**対話フロー**:
1. テーマ未指定なら、今週の素材から候補を3つ提示（各1行）。ユーザーが選ぶ。
2. 骨子の壁打ち: 「主張1文→根拠2つ→予想される反論→応答」の骨格をユーザーに埋めさせる。AIは穴を指摘するだけ。
3. ユーザーが本文を書く（段落ごとに投げてよい）。AIの添削は「論理の飛躍・概念の誤用・事実誤認」の3観点のみ。**文体には触れない。代筆しない**（リライト案の提示は1段落につき1回まで、ユーザーが明示的に求めた場合のみ）。
4. 保存: `essays/drafts/YYYY-MM-DD-<slug>.md`（§2.4 frontmatter、`status: draft`）。
5. `--publish <slug>`: ユーザーから公開先URLを聞き、`git mv` で `published/` へ移動、`status: published` と `published_url` を更新。

**書き込み**: `essays/drafts/`（新規/更新）または `published/` への移動。

**コミットメッセージ**: `essay: draft <slug>` ／ `essay: publish <slug>`

### 4.6 `/review` — 週次・月次・四半期レビュー

**目的**: 進捗集計→振り返り対話→記録→シラバス調整、の運用サイクルを回す。

**引数**: `week`（既定）| `month` | `quarter`。

**読むファイル**: ①対象期間の `daily/**/*.md` 全件のfrontmatter ②期間内に作成・更新された概念カードのfrontmatter（`created` と `review_history` の日付で判定） ③期間内の `news/`・`essays/` ④前回の同種レビュー（あれば、特に「次の期間の目標」） ⑤ `curriculum/syllabus.md` と `roadmap.md`。

**対話フロー**:
1. **集計を提示**（AIが機械的に算出。問いより先に事実）: セッション数・合計分数・平均分数、新規概念数、レベル昇格イベント数、復習pass率、エッセイ本数、streakの推移、シラバス消化率（計画rangeに対する実績）。
2. **振り返り対話**（3問固定）: 「一番腑に落ちたことは？」「一番詰まった・つまらなかったことは？」「計画とのズレの原因は量・難度・興味のどれ？」
3. **記録**: `templates/review-*.md` から `reviews/{weekly|monthly|quarterly}/` に保存（§2.4 frontmatter＋対話の要点＋「次の期間の目標」3つ以内）。
4. **シラバス調整**: ズレに基づき来週（来月）のブロック案を提示。**ユーザー承認後に** `syllabus.md` を更新し、`## 変更履歴` に1行追記。今週ブロックの `status` も確定（`done`/`skipped` 等）。月次ではフェーズ進行の判断（`roadmap.md` の完了条件と照合）、四半期では `roadmap.md` 自体の見直し提案まで行う。
5. `progress.md` 再生成。

**書き込み**: `reviews/...`（新規）、`curriculum/syllabus.md`（承認後）、月次・四半期では `curriculum/roadmap.md`（承認後）、`progress.md`。

**コミットメッセージ**: `review: 2026-W24` ／ `review: 2026-06` ／ `review: 2026-Q2`

## 7. git運用

**決定: 自動コミットを採用する。** 各コマンドの終了処理内で実行する。

理由: (1) 「保存し忘れ」をゼロにし、毎日の摩擦を最小化する（続けることが最優先の制約） (2) コミット履歴がそのまま学習ログになり `git log --oneline` が第二の進捗表示になる (3) 単独利用のリポジトリでありコンフリクトのリスクが実質ない。

懸念と対策: 「ゴミも記録される」→ 学習ログでは履歴の完全性の方が価値が高い。整形したければ後からでよい。「コミット粒度」→ 1セッション=1コミットで粒度として適切。

**終了処理の規範手順**（各コマンド共通）:

```bash
git add -A
git status --short          # AIが目視確認: 意図しないファイルが混ざっていないか
git commit -m "<§4の規約に従うメッセージ>"
```

- **push は自動では行わない**（既定）。ネットワーク・リモート障害でセッション完了がブロックされるのを防ぐ。例外として `/review` の終了処理でのみ `git push` を**試行**し、失敗しても警告表示のみで続行（リモート未設定なら黙ってスキップ）。
- コミットメッセージ規約（§4 各コマンド参照）: `<command>: <date or 対象> (<補足>)` の1行。本文・トレーラー不要。
- 途中保存はしない（セッション中にコミットしない）。中断時はユーザーが明示的に「ここまで保存して」と言えば同じ手順で実行。
- `.gitignore`: `.DS_Store` / `*.swp` / `.claude/settings.local.json` の3行。

## 11. 統合時の調整（2026-06-10 改訂。本文と矛盾する場合は本節が優先）

設計統合レビューで確定した上書き事項:

1. **/today の引数**: なし / `short`（30分版・ニュース適用スキップ）/ `min`（最小デー10分版: 想起1〜2問→5分ミニインプット→一行ログ。method/rules.md §2 の正規運用モード）。
2. **/today の復帰モード**: 直前の日次ノートが3日以上前なら、想起をスキップして直近2週間の要約から軽く再開する（旧 /restart 案を吸収）。
3. **概念カードの本文セクション**: §2.2の4セクションを8セクションに拡張 — 一行定義（自分の言葉）/ 出典と文脈 / 現代の例（技術・ビジネス）/ 誤用・俗流理解 / この概念が立てる問い / 関連・対比 / 適用ログ / 訂正ログ。**作成時に埋めるのは上3つだけでよい**（残りは復習・適用・エッセイで育てる）。「一行定義」「この概念が立てる問い」はユーザー本人の言葉（AIは添削のみ）。
4. **カード作成ペース**: 1日最大2枚（本文どおり）＋週2〜4枚を目安とする。読書中に出会った概念は `concepts/_inbox.md` に1行メモしてよい（frontmatterを持たないためSRSスキャン `grep '^next_review:'` には載らない）。
5. **公開ペースの正典**: method/rules.md §3.2（Day 1〜14 エッセイなし → W3 下書き → W4 からX任意 → 3ヶ月でブログ昇格）。
6. **週の型**: 月〜金 `/today`、土 `/essay`（＋任意 `/talk`）、日 `/review week`。月末日曜は `/talk speech` → `/review month`。
7. **ロールモデル**: 東浩紀 × 中島聡。`/essay` は型A（哲学エッセイ: training.md §6.2）と型D（中島聡型テック時評: training.md §5(d)）の2型を提示する。
8. **立ち上げ期**: Day 1〜14 は `/today`（30分版相当）のみ。45分版と `/essay` は Day 15 解禁（method/rules.md §9）。
